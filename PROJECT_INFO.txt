2. ARCHITECTURE AND KEY FILES
-----------------------------

Backend:
- backend/server.js is the Express entry point. It serves frontend/dist when
  available, enables CORS and JSON parsing, and listens on PORT (default 5000).
- POST /api/parse-expense
  Accepts text, month, and year; parses the transaction; assigns the requested
  month/year date; then stores it in the backend in-memory array.
- GET /api/expenses?month=MM&year=YYYY
  Returns month-bounded transactions sorted newest first.
- DELETE /api/expenses/:id
  Deletes a local in-memory transaction.
- POST /api/text-to-speech
  Legacy ElevenLabs TTS endpoint. It returns MP3 audio when configured and a
  fallback response otherwise. Current React UI has TTS disabled.
- GET /api/health
  Reports server status, Ollama host, and Ollama model.
- parseWithOllama sends /api/generate to Ollama with temperature 0 and a strict
  JSON schema containing amount, category, merchant, and type. It sanitizes the
  amount and normalizes missing values.
- fallbackParseTransaction is the heuristic offline parser. It detects numeric
  amounts, income keywords, categories, and known merchants. The Ollama error
  path currently calls fallbackHeuristicParser; the defined function is named
  fallbackParseTransaction and should be aligned if that path is exercised.
- parseWithGemini is not implemented in the current backend, despite the
  @google/genai dependency. There is no active Gemini fallback path.
- Storage: inMemoryExpenses stores transactions for the backend process lifetime.
  Each record uses a local_ timestamp-based string ID.

Frontend:
- frontend/src/App.jsx owns month/year selection, expense loading, natural
  language submission, deletion, category filtering, sorting, totals, and
  export-related props.
- frontend/src/components/HeroInput.jsx provides text transaction input and
  submits to the backend parser.
- frontend/src/components/Header.jsx provides month/year controls.
- frontend/src/components/SummaryCards.jsx renders filtered spending, income,
  and net balance.
- frontend/src/components/TransactionList.jsx renders filtered/sorted
  transactions, deletion controls, and Excel-compatible CSV export.
- frontend/src/components/CategoryChart.jsx renders the Chart.js doughnut
  breakdown and exports the full chart/legend composition as PNG or JPG.
- Category filtering uses selectedCategory, default "All". Sorting uses sortBy,
  default "newest"; supported modes are newest, oldest, amount-high, and
  amount-low. The filtered/sorted array feeds the transaction list, summary
  cards, and chart.
- Current React UI has no active voice STT/TTS integration. Legacy voice code
  remains in frontend/app.js and the backend TTS endpoint. The prior React
  ElevenLabs/Web Speech calls were removed.

3. ENVIRONMENT AND SETUP
------------------------

Backend keys from backend/.env.example:
- PORT
- OLLAMA_HOST
- OLLAMA_MODEL
- SENTRY_DSN
- ELEVENLABS_API_KEY
- ELEVENLABS_VOICE_ID

AI_STUDIO_KEY / Gemini credentials are not present in the current .env.example
and are not consumed by backend/server.js.

Typical setup:
- Backend: cd backend; npm install; npm start
- Frontend development: cd frontend; npm install; npm run dev
- Production frontend: cd frontend; npm run build; backend serves frontend/dist
- Ollama is expected at OLLAMA_HOST with the configured model. Transactions are
  held in backend memory and mirrored to browser localStorage by the frontend.

4. FEATURES AND EDGE CASES
---------------------------

- INR number rules are included in the Ollama prompt:
  "four fifty" -> 450; "four hundred fifty" -> 450;
  "fifteen hundred" -> 1500; "two thousand" -> 2000.
- Amounts are converted to Number and invalid/non-positive values become 0 in
  Ollama result sanitization. The heuristic parser defaults to 100 when no
  numeric amount is found.
- Ollama category/type values are constrained by a strict JSON schema and
  normalized after parsing.
- Parser fallback is intended to keep offline operation working through
  keyword-based category, income, merchant, and amount detection.
- Month filtering uses transaction dates and is applied by the frontend.
- Export filenames include the active category filter, month, year, and
  transaction sort (CSV), or category filter/month/year and image format
  (chart). Empty exports are disabled.
